# Windows 登录示例

`login.ps1` 使用 PowerShell 7。指定目标校园账号后，脚本根据当前宽带绑定决定是否迁移，再登录并核对门户身份。指定 `-Probe` 时另外观测公网通达性。一次运行从网卡查询开始使用同一个 CLI `session`，复用门户上下文和各账号的管理会话，完成后统一退出管理会话。

先将 `njupt-net` 放入 PATH，按照 [配置示例](../../config.example.json) 准备当前目录的 `config.json`。账号参数使用配置 `accounts` 中的键。通过 `njupt-net interfaces` 查看网卡名与 IPv4；以下命令中的 `Ethernet` 替换为校园网网卡名。

以下命令从仓库根目录运行；使用 Windows ZIP 时，从解压根目录运行。`-Config` 的相对路径按当前工作目录解析，`-Executable` 可指定解压得到的可执行文件。

## 使用

在 `config.json` 的 `accounts` 中填写校园账号与密码，在 `broadband_account` 中填写宽带账号、密码，以及 `njxy` 或 `cmcc` 运营商。`-Account` 选择要登录的校园账号键；运营商直接取自宽带配置。

```powershell
pwsh -NoProfile -File examples/windows/login.ps1 -Interface Ethernet -Account ACCOUNT_ALIAS
```

网卡有多个 IPv4 时，通过 `-Source` 选择具体地址：

```powershell
pwsh -NoProfile -File examples/windows/login.ps1 -Source SOURCE_IPV4 -Account ACCOUNT_ALIAS
```

## 参数

| 参数 | 含义 | 默认值 |
|---|---|---|
| `-Account ALIAS` | 目标校园账号在配置中的键 | 必填 |
| `-Interface NAME` | 选择校园网网卡，与 `-Source` 二选一 | 必须选择一种 |
| `-Source IPv4` | 选择校园网网卡上的源 IPv4，与 `-Interface` 二选一 | 必须选择一种 |
| `-Config FILE` | 校园账号与宽带配置文件 | 当前目录的 `config.json` |
| `-Executable COMMAND` | `njupt-net` 可执行文件路径或命令名 | PATH 中的 `njupt-net` |
| `-TimeoutSeconds SECONDS` | 传给 CLI 的单次网络请求超时 | `15` |
| `-PortalPort PORT` | 门户端口，可选 `801/802/803/804`；801、803 使用 HTTP，802、804 使用 HTTPS | `801` |
| `-BindingTimeoutSeconds SECONDS` | 本次新绑定后允许等待认证生效的时间，范围 `0..120` 秒 | `45` |
| `-Probe` | 登录确认后额外探测公网通达性 | 关闭 |

一次执行固定使用最初选定的源 IPv4。脚本先查询网卡并取得该源 IPv4 的互斥锁，再发送校园网络请求；同一源 IPv4 已有流程运行时，新流程报告正在使用并结束。执行期间持有配置文件的只读句柄，Windows 阻止写入、删除和替换，CLI 使用同一份凭据快照。

## 目标状态

脚本以目标校园账号持有配置中的宽带、当前终端使用该账号和运营商在线为完成状态。先读取目标账号在所选运营商下的绑定，再决定处理方式：

| 目标账号当前绑定 | 处理方式 |
|---|---|
| 账号等于配置中的宽带账号，且密码已设置 | 保留现有绑定 |
| 账号、密码均为空 | 查询其他配置账号，寻找这条宽带的当前持有人 |
| 已绑定另一条宽带，或账号、密码只有一项为空 | 报告当前绑定不符合要求并结束 |

目标绑定为空时，其他配置账号中有唯一持有人便迁移到目标；没有持有人便直接绑定目标；发现多个持有人时结束。宽带持有账号与终端当前登录账号分别确定，两者可以不同。

当前终端已经使用目标账号、正确运营商在线时，脚本保留当前会话：绑定已符合配置便完成；需要迁移或绑定便只修改宽带关系，再确认门户仍为目标身份。绑定后门户已离线时，继续执行目标账号认证。

当前终端使用其他账号或运营商在线时，脚本通过 Self 按本机校园网 IPv4 与 MAC 选定唯一会话，下线前再次核对目标与持有人的绑定、原身份与 MAC，再完成必要的宽带迁移或绑定，使用目标账号认证。当前在线身份须能唯一对应配置中的校园账号；未知或歧义身份会返回错误。

门户显示离线时，脚本直接继续所需的迁移、绑定和登录。修改前重新读取目标及已找到持有人的绑定，完成后核对门户目标身份与绑定结果。Self 在线列表用于定位需要下线的账号会话；当前终端是否在线由门户状态确定。所有门户操作使用同一个 `PortalPort`。

绑定与解绑由内核提交后重新读取表单，精确核对目标字段。提交新绑定后，脚本立即尝试门户认证；如果门户明确拒绝且完整提示为“未绑定运营商账号,请正确绑定运营商账号再试！”，当前请求完成后便在剩余时间内立即再次认证，首次成功即继续。认证始终串行执行。`BindingTimeoutSeconds` 表示这段生效窗口，限制下一次认证的启动时间；已发出的请求使用 `TimeoutSeconds`。设为 `0` 时只尝试一次。已有绑定直接登录、已经正确在线的路径按当前状态继续。

门户登录返回已核验的在线状态，脚本直接用该结果核对源 IP、目标账号、运营商与 MAC。每个账号的 Cookie 与身份单独保存，重复读取仍向服务器查询当前状态。

下线操作选定本机会话；内核在提交前重新读取当前账号在线列表，确认精确 session ID 仍存在，提交后确认该会话消失，脚本再确认门户已离线。宽带绑定属于校园账号级关系，迁移后由目标校园账号持有。

每次内核调用只提交一次修改。外层再次认证仅用于本次新绑定后的上述明确拒绝；网络异常、未知结果、认证接受后核验失败及其他拒绝均结束流程，保留已经完成的步骤。指定 `-Probe` 后，公网探测结果另行报告，已确认的门户登录保持成功。再次手动运行时，脚本重新读取当前状态，决定还需要哪些操作。

## 桌面入口

本机桌面入口调用同一个 `login.ps1`，通过 `-Account` 选择目标账号，并使用绝对路径指定脚本、`-Config` 和 `-Executable`。这样从桌面启动时仍读取指定配置。不同账号的入口只需改变目标账号参数。

## 结果

门户身份与宽带绑定确认后，脚本向标准输出写入一份 JSON，退出码为 `0`。业务步骤失败时，向标准错误写入一份 JSON，退出码为 `1`。`data.stage` 标明执行到的阶段，`data.steps` 记录已执行步骤及其结果；失败结果同样保留这些信息，便于查看当前终端与绑定状态。

指定 `-Probe` 后，公网观测单独保存在 `data.internet` 和 `data.internet_error`；默认两项均为 `null`：

| 观测结果 | `data.internet` | `data.internet_error` |
|---|---|---|
| 探测确认端点可达 | `true` | `null` |
| 探测明确返回未通过 | `false` | 探测错误说明 |
| DNS、连接等错误导致未取得结果 | `null` | 探测错误说明 |

以上观测均保留已确认的登录结果，退出码为 `0`。探测通过系统 DNS 解析外部域名，再以选定源 IPv4 建立 TCP 连接。

结果的 `command` 为 `login`。`data.account_alias` 是目标账号，`data.portal_port` 是本次门户端口，`data.previous_account_alias` 记录原在线账号，`data.binding_from` 记录迁移前的宽带持有人，`data.binding_moved` 表示本次宽带迁移是否已完成。`data.login_attempts` 记录门户认证次数，保留目标门户会话时为 `0`；`data.binding_activation_seconds` 记录新绑定后的认证阶段用时，保留已有绑定或目标门户会话时为 `0`。`data.steps` 中的 `elapsed_ms` 记录每次 CLI 调用的用时。

校园账号和宽带密码由 CLI 从配置文件读取。脚本通过 CLI 的 JSON 结果核对状态，密码保留在配置文件中。
