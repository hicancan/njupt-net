# 门户会话与自助在线记录

## 两个会话空间

门户 `eportal/portal/online_list` 返回接入终端的 `user_account`、`online_ip`、`online_mac` 和 `online_session`。自助服务 `dashboard/getOnlineList` 在已认证的管理账号下返回 `sessionId`、`userId`、`ip`、`mac` 和计费信息。

两组会话编号分别属于各自接口。在线观察中，同一终端可以在门户显示一个账号，而自助记录出现在另一账号下；也可以门户在线、外网可用，而自助列表没有该终端记录。官方网页登录和直接接口认证均出现过这类状态。

## 下线动作的定位与确认

需要切换当前上网身份时，登录脚本先确认门户当前账号，再在该账号的自助在线列表中以 IP 与 MAC 唯一定位连接。`dashboard/tooffline` 使用此列表返回的精确 `sessionId`。内核提交前重新确认该 ID 存在，接受后观察其从列表消失；脚本另外观察门户转为离线。

是否需要下线由门户身份与目标账号、运营商是否一致决定。身份已经符合目标时，仅处理尚需完成的宽带关系；改绑后核对门户仍为目标身份且 MAC 保持一致，实际离线时再认证。其他身份在线时，Self 列表用于定位待清退的精确连接。门户已经离线时，脚本直接继续绑定与认证。

管理记录消失、门户离线和实际数据连接停止分别观察。现场实验在自助列表出现当前接入的在线记录后，使用该记录的 `sessionId` 执行下线；随后确认 Self 记录消失、门户显示离线，绑定校园物理网卡的公网 HTTP 请求返回门户重定向。这些结果共同确认该次下线已经作用于当前接入。

同一观察中，801 与 804 的标准门户注销请求均返回“获取用户在线信息数据为空！”。后续 Self 连接清退使用其实际返回的 session ID，并以门户状态和校园物理连接响应确认结果。两项接口各自保留本次服务器响应。

## 接入上下文的来源

网页脚本可以从页面 URL 的查询参数读取 `wlan_ac_ip`、`wlan_ac_name` 等接入信息。实际离线请求返回 HTTP 302，`Location` 为 `http://10.10.244.11/a79.htm`，没有查询参数。该跳转提供门户入口，本身没有提供 AC IP 或 AC 名称。

直接访问 `eportal/portal/index` 获得的是通用模板；`index/getClientIp` 提供终端 IP，`page/loadConfig` 提供认证策略。研究时分别保存模板、策略配置和实际重定向地址，依据响应中出现的字段确认接入上下文。
